LESSON 02 / 12
聊天機器人 vs Agent

差別在「如何推進任務」

一般聊天介面：以生成文字回答為主。
Agent：可根據任務決定是否呼叫工具，取得結果後再決定下一步。是否屬於 Agent 要看實際控制流程。

從一個任務開始

幫我整理三份資料

① 接收整理需求 → ② 檢索資料 → ③ 檢查來源 → ④ 彙整重點 → ⑤ 輸出摘要。
這是 Wiki 中的教學示例，不代表系統已實際連接搜尋服務。

LESSON 04 / 12
Agent 的核心組件

模型 × 指令 × 工具

模型（LLM）：理解任務、判斷下一步。指令與規則：設定目標、格式與界線。
工具：讀檔或檢索資料；上下文／狀態：保存當前任務資訊；安全護欄：必要時加入審核。

LESSON 05 / 12
工具呼叫如何運作

提出呼叫 ≠ 工具已執行

模型產生工具呼叫 → 應用程式執行工具 → 回傳結果 → 模型繼續判斷。
工具失敗或沒有結果時，不能假裝已成功取得資料。

LESSON 06 / 12
Agent Loop

一個常見的五步驟循環

① 收到任務 → ② 判斷資料與工具 → ③ 執行工具 → ④ 觀察結果 → ⑤ 繼續或停止。
核心不是無限重複，而是依照新資訊決定下一步。

LESSON 07 / 12
什麼是 Workflow？

固定路徑 vs 動態決策

Workflow：開發者預先設定主要步驟與路徑。
Agent：模型在允許範圍內動態選擇工具與行動。兩者可以搭配使用。

LESSON 08 / 12
Graph 與回退關卡

把流程畫成可檢查的節點

Wiki 檢索 → 覆蓋率檢查 → 證據卡 → 大綱 → 人工確認 → 逐頁稿 → 忠實度 → HTML → 渲染檢查。
若內容無來源，回逐頁稿；若 Wiki 覆蓋不足，停止並補資料；若版面溢出，回排版修正。

LESSON 09 / 12
平行與多 Agent

分工不等於一定更好

平行證據卡：不同主題可分開檢索，再合併去重。
任務複雜時可拆分角色；簡單任務先用單一流程，避免不必要的複雜度。

LESSON 10 / 12
AI Agents 的風險

錯誤可能沿著流程放大

常見問題：資料不足卻回答、來源不支持主張、工具失敗、外部內容帶有不可信指令。
因此每個重要輸出都應有來源與檢查點。

LESSON 11 / 12
讓 Agent 更可靠

把檢查放在生成之前

先檢查 Wiki 覆蓋率，再整理證據卡；逐頁稿完成後檢查忠實度；渲染後檢查排版。
只修正不合格頁面，並保留修正紀錄；重要決策安排人工確認。
